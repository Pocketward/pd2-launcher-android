# What pack.sh leaves out of FEX's Ubuntu 24.04 RootFS (1.8 GB unpacked) before it
# packs the runtime. One bash glob per line, relative to the RootFS (globstar on; L stands for
# usr/lib/*-linux-gnu, both the i386 and the x86_64 library folder). '#' starts a comment.
# pack.sh fails if an ELF file it keeps, in the RootFS or in Wine-GE's own lib and lib64 folders,
# names in DT_NEEDED a library that the trim leaves no 32-bit (i386) or 64-bit (x86_64) copy of,
# matching that file's class. What is loaded with dlopen() is not checked that way: Wine's own
# dlopen() list (strings in lib/wine/*-unix/*.so: X11 and its extensions, glvnd
# libGL/libGLX/libEGL, the Vulkan loader, FreeType, Fontconfig, GnuTLS, PulseAudio, ALSA, SDL2,
# GStreamer, Kerberos, CUPS, D-Bus, udev, ...) stays by hand.

## Guest Mesa. The game draws through FEX's 32-bit GL thunk: FEX overlays the guest's libGL.so.1
## with its thunk (ThunksDB "GL", Data/ThunksDB.json), so the guest's GLX vendor library, Mesa's
## gallium megadriver and the libLLVM it links are never loaded; the GPU work is done by the App
## userland's ARM64 Zink on Turnip or PanVK. The guest's Turnip is built for the Linux msm driver
## only, and its other Vulkan drivers (Intel, Radeon, Nouveau, Asahi, lavapipe, Dozen) have no
## device here.
## Kept: the glvnd dispatch libraries (libGL, libGLX, libGLdispatch, libEGL, libOpenGL), libdrm
## and the Vulkan loader, which Wine dlopens by name, libgbm, which SDL2 (winebus) links, and
## libva, libva-drm and libva-x11 (both classes; their drivers in dri/ go), which Wine-GE's own
## FFmpeg (lib{,64}/libavutil.so.56, libavcodec.so.58) and libgstva-1.0.so.0 link.

L/dri
