# Mesa patches for PanVK on kbase

Applied by `build-panvk.sh`, after `../mesa/`, to the Mesa tree pinned by `config.sh` (`PANVK_MESA_*`: the same commit of main as `MESA_*`). The kbase pan_kmod backend's own files are not patches: they live in `../../mesa-kbase/` and are copied over the patched tree.

- `0001-panfrost-kmod-kbase-backend-and-hooks.patch`: registers and builds the kbase backend in `src/panfrost/lib/kmod`; adds optional `pan_kmod_ops` hooks (panthor command-stream ioctls, CSF interface info, flush id, sync-update notify), `pan_kmod_dev_props.limits`, the `GPU_SYNC` BO flag and `fixed_va`.
- `0002-panvk-run-on-kbase.patch`: PanVK enumerates `/dev/mali0` and runs on the kbase backend: kmod accessors in the CSF queue code, VA heaps from the backend's range, GPU-map before CPU-map, no mirror mapping, sparse binding, placed maps or fd sharing where the backend has none, waited-on sync objects in `GPU_SYNC` memory, `vkSetEvent` notifies the kernel.
- `0004-panfrost-crc-clear-colour-hash.patch`: a 64-bit mixing hash for the CRC clear colour, so different clear values do not collide and transaction elimination does not skip a clear.
- `0005-panvk-import-dma-bufs-on-kbase.patch`: a backend without fd sharing may still import dma-bufs (`limits.dma_buf_import`); PanVK then offers `VK_KHR_external_memory_fd` and `VK_EXT_external_memory_dma_buf`, reports dma-bufs as importable only (images only linear), and maps a BO the backend placed itself (`fixed_va`: an import on kbase, or every BO in the kernel-placed mode) at that VA, refusing an opaque capture address for another VA; a bind that would put an interleaved 64K image at a VA not 64 KiB aligned is refused. With it, the WSI's direct present (`../mesa/0004`) imports the app's buffers on kbase.
- `0006-panfrost-model-mali-g710.patch`: a `pan_model_list` entry for the Mali-G710 (product id 10.8.2), with the G610's values (the same Valhall v10 design); without it `pan_get_model()` finds no model and PanVK refuses the GPU.
- `0007-panvk-ring-buffer-at-the-backend-va.patch`: a render descriptor ring buffer whose BO the backend placed itself (`fixed_va`) is bound at that VA, which must be aligned to twice the ring size, and its VA is not given back to the heap. kbase places every BO itself on a kernel without `MEM_ALLOC_EX` (MediaTek's r32p1 kbase, which reports CSF uAPI 1.18); without this patch `vkCreateDevice` fails there.
